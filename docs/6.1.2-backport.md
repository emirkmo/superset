# Local 6.1.2 backport

This local release extends the `6.1.1` tag
(`db6b16701a7e633ac5ffc50fa67b91f0fca9e343`) and its required-filter
default fix. It is not an Apache Superset release. The source baseline for both
local releases is Apache's official `6.1.0` tag
(`c83fb2bb1dcfac41ac51bcebd82471f4a7180d18`), which matches the source
label of `apache/superset:6.1.0-py312`.

## Changes

- [PR #40984](https://github.com/apache/superset/pull/40984), upstream merge
  `e08c2c12dad7cf8108a3be6b8d9cd638bc0e8fd6`: retain typed and pasted
  values in creatable select filters and normalize pasted tokens.
- [PR #43859](https://github.com/apache/superset/pull/43859), upstream merge
  `613871ed3633ee0b4dcba5a237dd50a7239070d5`: keep the default-value
  filter state stable across unrelated rerenders.
- [PR #40528](https://github.com/apache/superset/pull/40528), upstream merge
  `aba6ea536ccf86a5e3af2ded4b1cae284ce20f87`: preserve dashboard owners
  by ID when the async select has only a partial option cache.

The first two PRs form one dropdown fix. The owners fix is independent.
The #40984 test patch requires adaptation to the 6.1 test harness because it
references later tests and helpers absent from this baseline. The merged PR
adds a whitespace-paste test for synchronous `Select` without changing its
untrimmed production path, so this backport applies the same token
normalization there as in the PR's `AsyncSelect` change. The test also asserts
the exact emitted values; checking rendered text alone misses leading spaces.
The #43859 test uses typed form fixtures in place of upstream `any` casts.

The #40528 source cherry-picked without conflicts. A component regression test
adds two owners, removes one, and verifies that the remaining owner preserves
its name and email even when absent from the async option cache. It also
checks the saved owner IDs. No dependency, backend, database migration, or
Dockerfile changes are included.

## Validation and review

- The 12 focused suites for dropdowns, dashboard owners, and the 6.1.1
  required-filter backport passed: 281 tests. After typing the new fixtures,
  the two affected suites passed again: 18 tests; the owner component and
  helper suites also passed together: 22 tests.
- With only the synchronous `Select` token normalization removed, its exact
  paste-value regression failed (`" b"` instead of `"b"`); it passed after
  restoring the fix.
- Replacing the owner helper's ID-based lookup with the old index-based logic
  failed the partial-cache and reordered-option tests; both passed after
  restoring the fix. The modal test also failed with that old logic.
- Reintroducing a new filter-state object on every `DefaultValue` render
  failed its identity regression; it passed after restoring memoization.
- An independent agent reviewed the owner and dropdown source changes against
  their upstream patches and found no blocking production issues. The review
  confirmed that the owner and #43859 production patches match upstream;
  #40984 differs only by the narrow synchronous Select correction.

The repository-wide TypeScript emit build reports errors in unrelated existing
source and declaration files, including `@types/d3` declarations. Targeted
type checks of the changed TypeScript files are used for this backport. A
browser-based save/reopen test requires a running Superset instance and is not
part of the automated validation above.

## Build

To build the same lean Python 3.12 variant used by the deployed Apache image:

```bash
git switch --detach 6.1.2
docker build --target lean \
  --build-arg PY_VER=3.12.14-slim-bookworm \
  -t superset:6.1.2 .
```

The release build publishes the `linux/amd64` image to
`ghcr.io/emirkmo/superset:6.1.2`. Pin deployments to its reported manifest
digest after publication.

## Deployment smoke tests

In a disposable or staging Superset instance, configure a creatable multiselect
native filter with comma-separated default values. Type and paste values,
including spaces after commas, save, close, and reopen its configuration.
Confirm the chips remain selected and dashboard queries include the defaults.
Repeat with a single-select filter and with creation disabled. Reopen the modal
and type into the dropdown while existing values are selected; unrelated
rerenders must not clear the text or selection.

On a dashboard with multiple owners, open Properties, add two users, remove one
original owner, and save. Reopen Properties and confirm all expected owners and
their names remain. Check that the save request contains the expected owner IDs.

Also rerun the `6.1.1` smoke test: a dashboard with a required default filter
must apply that value on initial load without a manual refresh.
