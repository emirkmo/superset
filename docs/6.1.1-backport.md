# Local 6.1.1 backport

This local build is based on the official `6.1.0` tag
(`c83fb2bb1dcfac41ac51bcebd82471f4a7180d18`) and backports only
[PR #40470](https://github.com/apache/superset/pull/40470), upstream commit
`01ed81785e51bd9c408b6d06baf65361f5b51042`. The `6.1.1` tag identifies this
local build; it is not an Apache release.

## Scope and conflict resolution

Required filters restore their configured defaults when a persisted mask is
empty or lacks the query data needed to filter charts. Editing a required filter
with empty state no longer overwrites its default, and a newly selected value
enables Apply even when it has no matching entry in the applied mask.

The cherry-pick conflict in `src/dataMask/reducer.test.ts` was resolved by adding
only the upstream range-filter regression test to the 6.1 tests. Adjacent tests
for unrelated chart customization changes from master were excluded. Production
changes match the upstream patch. Additional tests cover hydration, optional
clears, valid saved selections, and `defaultToFirstItem` behavior.

An incomplete saved selection with a value but no query data falls back to the
configured default, as specified by the upstream fix. Dependency versions,
backend code, database migrations, and Docker build logic are unchanged.

## Build locally

From the repository root:

```bash
git switch --detach 6.1.1
docker build --target lean \
  --build-arg PY_VER=3.12.14-slim-bookworm \
  -t superset:6.1.1 .
```

The explicit `lean` target builds the production frontend and backend. The Python
argument matches `apache/superset:6.1.0-py312`: Python 3.12.14 on Debian
Bookworm. Apply your deployment's existing database drivers and configuration to
this image as usual. The package version is `6.1.1`; the lockfile changes only
its root version fields.

## Validation

Run the focused suites from `superset-frontend`:

```bash
npm run test -- --runTestsByPath \
  src/dataMask/reducer.test.ts \
  src/dataMask/reducer.backport.test.ts \
  src/dashboard/components/nativeFilters/FilterBar/utils.test.ts \
  src/dashboard/components/nativeFilters/FilterBar/FilterBar.test.tsx \
  --maxWorkers=2
```

For deployment smoke testing, load a dashboard with a required default filter
several times, including through a permalink. Confirm that chart queries contain
the default filter without refreshing. Change the configured default and confirm
it applies; manually change a value and confirm Apply enables. Also check that
clearing an optional filter remains possible.
